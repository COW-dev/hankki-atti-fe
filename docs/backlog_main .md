# 백로그

## 표 작성 기준

- 첨부된 백로그의 원본 표와 같은 `할 일 · 내용 · ID · 상태 · 담당자 · 비고` 열을 사용한다.
- 상태는 **완료 / 할 일 / 결정 대기**다. 최초 완료 17건(C-01~C-17)을 유지하고, 기존 미완료는 **할 일**로 표기한다. 이후 끝난 항목은 ID·위치를 그대로 두고 상태만 **완료**로 바꾼다. 담당자는 지정 전이므로 **미정**이다.
- **내용**에는 구현 범위·완료 조건·근거를, **비고**에는 우선순위와 선행 작업 또는 남은 관련 작업을 적는다. 정책 결정 항목의 협의 대상은 제안이며 담당자 배정이 아니다.
- P0/P1/P2는 요구사항 원본 기준이다. 원본에 우선순위가 없는 공통 기반·검증·결정 항목에는 **제안**을 붙인다. 기존 ID와 항목 간 참조를 유지한다.
- 범위는 사용자 앱과 관리자 페이지의 프론트엔드다. 관리자 구현 위치는 D-09에서 정한다. API·콘텐츠는 제공 여부를 확인할 외부 의존성이다.
- 완료는 기재된 범위의 코드 구현 확인을 뜻한다. 링크·임시 화면만 있는 기능은 완료가 아니며, 실행 테스트·실제 백엔드 연동·최신 Figma 조회까지 검증했다는 뜻은 아니다.
- API 경로·필드·오류 코드는 Swagger 확인 후 확정한다. 원본이 참조하는 “백엔드 요구사항 7장”은 로컬 원본에 포함되어 있지 않다. 저장소 규칙과의 충돌은 D-10~D-12에서 확인한다.

## 5. 검증 백로그와 공통 완료 조건

접근성은 각 기능의 완료 조건이다. 아래 검증은 개별 구현 시 검증을 대체하지 않고 화면 간 연동과 실제 이용을 확인한다.

[제목 없음](backlog/%EC%A0%9C%EB%AA%A9%20%EC%97%86%EC%9D%8C%203faf43623f8e802b9cb4fac9415de850.csv)

모든 구현 항목은 다음 조건을 적용한다.

1. 최신 “10 목업” 및 디자인 시스템을 해당 파일·노드로 조회하고 값·문구를 대조한다. 디자인 시스템 파일과 화면 파일의 노드 ID를 혼용하지 않는다.
2. `packages/ui`·용도 토큰·텍스트 스타일을 재사용한다. 신규 공용 동작은 구현·스토리·접근성 테스트를 함께 둔다.
3. 입력 label·required·오류 `aria-describedby`, assertive 오류 요약·첫 오류 포커스, inactive 버튼의 이유, 상태 텍스트·아이콘을 제공한다.
4. h1 하나, header/main/nav, 화면 이동 후 h1 포커스, 읽기/포커스/시각 순서, 조작 영역, 새 창 링크 이름을 확인한다. 모달과 비모달 패널의 포커스 동작을 구분한다.
5. 서버 호출은 `apiRequest`/`authRequest`, 오류 분기는 `ApiError.code`, 시각은 `parseLocalDateTime`과 Asia/Seoul 기준을 사용한다. 민감 정보 로그·토큰 영구 저장·클라이언트만의 권한 제한을 추가하지 않는다.
6. 새로 만들거나 바꾼 lib 로직과 공용 UI 동작에 요구된 테스트를 작성하고 오류·빈 상태·재시도·경합·중복 제출을 검증한다.
7. 커밋 전 `pnpm check`와 관련 검사를 통과한다. 인증의 토큰·쿠키 처리 변경은 사람 리뷰를 받는다. 화면 변경 PR에 필요한 스크린샷을 첨부한다.

### 이번 범위에서 추가하지 않는 기능

원본의 제외 조건도 구현 범위에 포함해 관리한다. 관리자 매칭 수동 변경·자동 패널티 적용, 도우미 가입 승인·관리자 도우미 등록, 공지 첨부·예약 게시·무한 스크롤·읽음 표시, 학생 프로필 직접 수정은 만들지 않는다. 매칭 전 학생 정보, 도우미에게 학생 장애 유형·전화번호, 학생에게 도우미 전화번호·예비 명단을 노출하지 않는다.

```markdown
# 백로그

>
> 양식 수정: 2026-10-15 (Asia/Seoul) · 브랜치: `docs/demand-backlog` · 기준 HEAD: `fd94641`
>
> 상태 갱신: 2026-10-22 (Asia/Seoul) · 브랜치: `main` · 기준 HEAD: `e67db0e` — PR #11·#12 코드 대조로 U-03·U-16~U-21만 재평가했다. 나머지 항목은 이전 평가를 유지한다.
>
> 요구사항 원본: [demand.md](../demand.md). 구현 상태는 최초 작성 기준 HEAD(`4ac695d`)의 코드 확인 결과를 유지한다. 이번 수정은 양식 변경이며 구현 상태를 재평가하지 않았다.

> 모든 항목이 완료되면 상단에 `✅ 완료 (날짜, 최종 병합 PR)` 배너를 붙이고 아카이브한다.

모든 구현 항목은 다음 조건을 적용한다.

1. 최신 “10 목업” 및 디자인 시스템을 해당 파일·노드로 조회하고 값·문구를 대조한다. 디자인 시스템 파일과 화면 파일의 노드 ID를 혼용하지 않는다.
2. `packages/ui`·용도 토큰·텍스트 스타일을 재사용한다. 신규 공용 동작은 구현·스토리·접근성 테스트를 함께 둔다.
3. 입력 label·required·오류 `aria-describedby`, assertive 오류 요약·첫 오류 포커스, inactive 버튼의 이유, 상태 텍스트·아이콘을 제공한다.
4. h1 하나, header/main/nav, 화면 이동 후 h1 포커스, 읽기/포커스/시각 순서, 조작 영역, 새 창 링크 이름을 확인한다. 모달과 비모달 패널의 포커스 동작을 구분한다.
5. 서버 호출은 `apiRequest`/`authRequest`, 오류 분기는 `ApiError.code`, 시각은 `parseLocalDateTime`과 Asia/Seoul 기준을 사용한다. 민감 정보 로그·토큰 영구 저장·클라이언트만의 권한 제한을 추가하지 않는다.
6. 새로 만들거나 바꾼 lib 로직과 공용 UI 동작에 요구된 테스트를 작성하고 오류·빈 상태·재시도·경합·중복 제출을 검증한다.
7. 커밋 전 `pnpm check`와 관련 검사를 통과한다. 인증의 토큰·쿠키 처리 변경은 사람 리뷰를 받는다. 화면 변경 PR에 필요한 스크린샷을 첨부한다.
```
