# /commit - 커밋 메시지 제안 및 커밋

## 역할
변경사항을 확인하고 Conventional Commits 형식의 커밋 메시지를 제안한다.
사용자 승인 없이 커밋을 실행하면 안 된다.
push는 절대 자동으로 실행하지 않는다.

## 실행 순서

### 1. 변경사항 확인
```bash
git status
git diff --cached
git diff
git ls-files --others --exclude-standard
```

### 2. 커밋 전 검사
```bash
pnpm check
```
실패하면 커밋하지 않고 사용자에게 보고한다.

### 3. 책임별 최소 단위 분할 (기본)
별도 요청이 없어도 변경사항을 **하나의 목적과 책임을 가진 최소 단위**로 나눈다.
파일 수나 커밋 수보다 각 커밋을 따로 설명·리뷰·되돌릴 수 있는지를 기준으로 한다.

- 같은 기능 작업이어도 공용 UI, 공통 레이아웃, 입력 검증·요청값 정리, 표시용 가공,
  API 연동, 화면 조립, 기존 화면의 진입 링크, 백로그 기록은 책임이 다르면 분리한다.
- 테스트는 검증 대상과, 스토리와 사용법 문서는 해당 컴포넌트와 묶는다.
  화면 전용 아이콘·에셋은 사용하는 화면과 묶는다.
- 서로 있어야만 의미가 있는 변경은 함께 둔다. 한 파일이라는 이유로 다른 책임을 합치거나,
  한 책임이라는 이유 없이 파일마다 기계적으로 쪼개지 않는다.
- 한 파일에 여러 책임이 섞여 있으면 필요한 변경 구간만 staging한다.
  분할을 위해 작업 트리의 코드를 임의로 수정하거나 기존 변경을 버리지 않는다.
- 기반 코드 → 이를 사용하는 코드 순서로 배치한다. 각 커밋은 앞선 커밋까지만으로
  타입·import·관련 테스트가 성립해야 하며, 뒤 커밋의 파일에 의존하면 안 된다.
- 커밋 메시지에 독립적인 목적을 여러 개 나열해야 한다면 더 나눌 수 있는지 다시 확인한다.

**분할 예시 — 관리자 학생 등록**

| 순서 | 책임 | 함께 묶을 변경 |
|---|---|---|
| 1 | 공용 선택형 입력 | TextField·테스트·스토리·디자인 시스템 문서 |
| 2 | 관리자 목록 복귀 | AdminShell·복귀 아이콘 |
| 3 | 등록 입력 검증 | 폼 모델·검증·요청값 정리·테스트 |
| 4 | 이메일 표시 가공 | 마스킹 함수·테스트 |
| 5 | 등록·계정정보 API | 요청 함수·응답 타입·오류 코드·테스트 |
| 6 | 등록 화면 | 화면·라우트·결과 아이콘·테스트 |
| 7 | 목록에서 등록 진입 | 목록의 등록 링크·목록 테스트 |
| 8 | 백로그 기록 | 진행 상태·구현 근거·남은 작업 |

예시의 개수를 맞추지 말고 실제 변경의 책임과 의존관계에 맞게 분할한다.

### 4. 커밋 메시지 작성

> 커밋 형식, type 종류, 제목/본문 규칙 → **AGENTS.md — Git 워크플로우 섹션 참고**

**핵심 요약**
```
<type>: <한글 제목 (명사형 종결)>

<한글 본문 — 왜 변경했는지, 어떤 문제를 해결했는지>
```

### 5. 사용자 승인 대기
커밋별 순서·메시지·포함 파일 또는 변경 구간을 표로 보여주고 검사 결과를 함께 보고한다.
분할안 전체에 대한 승인을 받으면 승인한 범위 안에서 순서대로 실행한다.
승인 후 분할 범위나 메시지가 달라져야 하면 실행 전에 변경안을 다시 승인받는다.

다음 중 하나를 선택하게 한다.
- 승인: 그대로 커밋 실행
- 수정: 수정 내용 받아 반영 후 재확인
- 취소: 커밋 중단

### 6. 커밋 실행 (승인 후에만)
각 단위마다 승인한 파일 또는 변경 구간만 staging하고, `git diff --cached`로
해당 책임의 변경만 포함됐는지 확인한 뒤 커밋한다. 기존 staging도 반드시 확인한다.

```bash
git add <파일 목록>
git diff --cached
git diff --cached --check
git commit -m "..."
```

모든 커밋 후 `git status --short`와 커밋 내역을 확인해 승인한 분할안과 일치하는지,
누락되거나 의도치 않게 남은 변경이 없는지 보고한다.

## 주의사항
- push는 절대 자동 실행 금지. 커밋 후 사용자에게 push 명령어만 안내
  ```bash
  git push origin <브랜치명>
  ```
- `git add .` 또는 `git add -A` 사용 금지 — 파일을 명시적으로 지정
- 다음이 staging에 포함되면 **즉시 중단**하고 사용자에게 경고
  - `.env.local` 등 `.env*` 파일 (`.env.example` 제외), `*.pem`, 자격증명 파일
  - `NEXT_PUBLIC_*`에 비밀값을 넣는 변경
- main 브랜치에서 실행 중이라면 커밋하지 말고 작업 브랜치를 먼저 만들도록 안내 (main 직접 커밋 금지)
